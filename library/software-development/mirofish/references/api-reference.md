# MiroFish API Reference & Provider Quirks

## Base URL
`http://localhost:5001/api/`

## Endpoints

### Project & Ontology
| Method | Endpoint | Description |
|---|---|---|
| POST | `/graph/ontology/generate` | Multipart: `files` + `simulation_requirement`. Creates project + generates ontology. Returns `project_id` + `graph_id`. |
| GET | `/project/<proj_id>` | Project details (files_count, text_length, status) |

### Graph
| Method | Endpoint | Description |
|---|---|---|
| POST | `/graph/build` | Build knowledge graph from project. Body: `{"project_id": "...", "chunk_size": 400, "overlap": 80, "reset": true}`. `reset=true` rebuilds from scratch. `chunk_size`/`overlap` control graph density (defaults ~250/50 = ~32 chunks; 400/80 = ~56 chunks). Returns `task_id`. |
| GET | `/task/<task_id>` | Poll task status (GRAPH_COMPLETED, GRAPH_BUILDING, etc.) |
| GET | `/graph/<graph_id>/entities` | View generated entities |

### Simulation
| Method | Endpoint | Description |
|---|---|---|
| POST | `/simulation/create` | Create simulation. Body: `{"project_id": "...", "graph_id": "..."}`. Returns `simulation_id`. |
| POST | `/simulation/prepare` | Generate config + personae + initial posts (3-5 min). Body: `{"simulation_id": "..."}`. Poll until status="ready". |
| POST | `/simulation/prepare/status` | Check fine-grained prepare progress. Body: `{"task_id": "..."}`. Returns `progress` (0-100%), `message` (stage info like "[3/4] generating_config: 1/3"), `status` (processing/completed/failed). |
| POST | `/simulation/start` | Start the run. Body: `{"simulation_id": "...", "platform": "parallel", "max_rounds": N}`. |
| GET | `/simulation/list` | List all simulations with status, round, progress |
| GET | `/simulation/<sim_id>` | Current status (runner_status, rounds, actions, progress, platform statuses) |
| GET | `/simulation/<sim_id>/profiles` | Generated personae (7 profiles typical) |

### Report
| Method | Endpoint | Description |
|---|---|---|
| POST | `/report/generate` | Generate final report. Body: `{"simulation_id": "..."}`. Response: `{"success": true, "data": {"report_id": "report_..."}}`. |
| GET | `/report/<report_id>` | Fetch report content |

### Health
| Method | Endpoint | Description |
|---|---|---|
| GET | `/health` | Backend health check |

## Provider Quirks

### MiniMax-M3 (`api.minimax.io/v1`)

- Uses `response_format={"type": "json_object"}` for JSON mode
- Produces reasoning tags (````) before the actual JSON response
- These reasoning tokens inflate completion counts by 2000-4000 tokens
- Typical ontology JSON output: ~6000-8000 raw completion tokens
- If `max_tokens` is set too low (default 4096), the JSON is truncated → parse failure
- Patch `max_tokens` to at least 8192 for ontology generation calls
- First ontology call: 60-90s. Subsequent calls: 30-40s.
- System prompt in ontology_generator is large → inflates context

### Zep Cloud

- GraphRAG + Persona Memory backend
- Hard limits: max 10 entity types, max 10 edge types
- Additional limit: each edge type's `source_targets` array is capped at **max 10 pairs**
- If the LLM-generated ontology produces edges with >10 source/target pairs, the Zep API returns: `source_targets cannot contain more than 10 items (max)`
- Fix: truncate `edge["source_targets"]` to max 10 in the ontology generator
- Do not generate more than these limits

## Simulation Config Parameters (as generated by LLM)

The LLM-generated config contains:
- `time_config`: Zielgruppe, Zeitzone, Tagesrhythmus, Agents-per-hour range
- `event_config`: Themen-Achsen, Persona-Rollen, polarisierte Positionen
- `agent_config`: 7 personae with bios, locations, karma, topics, MBTI
- `initial_posts`: 7 seed posts assigned to specific publishers

## Typical Persona Structure

```python
{
    "name": str,              # Display name
    "username": str,          # @handle
    "age": int,               # 20-50
    "country": str,           # ISO country
    "gender": str,            # male/female/other
    "profession": str,        # Job title
    "bio": str,               # 1-2 paragraph bio
    "persona": str,           # Deep persona description (history, personality, speaking style, triggers)
    "karma": int,             # 100-5000
    "mbti": str,              # MBTI type
    "interested_topics": [],  # 10-15 topics
    "created_at": str,        # YYYY-MM-DD
}
```

7 profiles are generated per simulation.
