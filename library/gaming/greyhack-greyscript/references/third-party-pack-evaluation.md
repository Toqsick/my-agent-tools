# Third-Party Code Pack Evaluation — GreyScript

> **Last used:** 2026-07-15 (GLM 5.2 Starter Pack)  
> **Methodology:** Systematic comparison of external AI-generated GreyScript pack against a hardened repo baseline.

## When to use

A third-party GreyScript code pack arrives (AI-generated by another model/agent, from Hub contributors, or from a different toolchain) and needs evaluation before merging/deploying.

## Evaluation Pipeline (7 Steps)

### Step 1: Extract + Inventory

```bash
unzip -l <pack>.zip                    # list content
unzip -q <pack>.zip -d /tmp/glm-review  # extract
find /tmp/glm-review -type f | sort    # full inventory
```

Key checks: missing `uicore.src`/`configcore.src`? Only tools, no cores? Missing `manifest.json`? That tells you scope immediately.

### Step 2: Similarity Scan (diff against hardened baseline)

Use `difflib.SequenceMatcher` per file to quantify divergence. Files under 0.50 similarity are essentially rewrites; files 0.75+ are polish passes.

```python
from difflib import SequenceMatcher
ours = open('repo/tools/yuno_nscan.src').read()
theirs = open('glm/all_fixed_sources/yuno_nscan.src').read()
sm = SequenceMatcher(None, ours, theirs).ratio()
# <0.5 = structural rewrite, 0.5-0.75 = significant rework, >0.75 = polish
```

Inspect diff hunks for noise: whitespace changes, comment rewrites, cosmetic renames (`SHOWUSAGE`→`showUsage`). High-hunk + low-add counts = mostly cosmetic.

### Step 3: P0 Pattern Scan

Scan both repos+pack with the known critical patterns. **Critical:** the pack must NOT regress fixes we already applied.

| Pattern | Regex | Why it matters |
|---------|-------|----------------|
| One-line ifs | `\bif\b.*\bthen\b.*\bend\s+if\b` | Breaks `greybel build` (Pattern a in build-breaker audit) |
| Bare module headers | `^(uicore|configcore|libcore|netcore)\s*$` (multi-line) | Runtime crash: "Path not found in scope" |
| Map methods without `@` | `\[".*"\]\s*=\s*(?!@)[A-Za-z]` | Function executes at assignment time instead of binding |
| `network_gateway` (v1) | `network_gateway` | Returns IP-string, not router object |
| `get_content`/`set_content` (no underscore) | `\.(getcontent|setcontent|getports)\b` | Wrong API — game uses `get_content`, `set_content`, `get_ports` |
| `range(n)` without guard | `range\([A-Za-z_.]*\.len\)` or `range\(0,\s*[^)]*\.len` | GreyScript `range(n)` is INCLUSIVE + DESCENDING — OOB crash |
| `hasIndex` on port objects | `p\.hasIndex\(` | Port objects are `typeof="port"`, not maps — `hasIndex()` crashes |
| `indexOf` != null | `indexOf\([^)]*\)\s*(==|!=)\s*null` | `indexOf` returns `-1`, not null |

### Step 4: Build Verification (`greybel build`)

Build every `.src` file in the pack:

```bash
for f in /tmp/glm-review/all_fixed_sources/*.src; do
  name=$(basename "$f" .src)
  out="/tmp/glm-build-$name"
  greybel build "$f" "$out" 2>&1
  echo "$name exit=$?"
done
```

**Real-world finding:** GLM pack's `setup.src` had 14 one-line ifs → greybel crashed with "no matching open if block" — immediate rejection signal.

### Step 5: Mock Execution

Execute each tool in Mock mode. Test all code paths (help, no-args, lan, ip):

```bash
# Test help
greybel execute tool.src -p "--help" -et Mock --silent
# Test default
greybel execute tool.src -et Mock --silent
# Test ip
greybel execute tool.src -p "192.168.1.1" -et Mock --silent
```

**What to watch for:** Runtime crashes (not build errors). The pack may build clean but fail at runtime from wrong API assumptions.

### Step 6: Cross-Reference Report Claims

If the pack comes with a report/readme, check each claim against real results:

| Report says | Reality check |
|------------|---------------|
| "Removed issues X, Y, Z" | Were X, Y, Z actually present? Did removal introduce new bugs? |
| "Fixed one-line ifs" | Actually check: did they or did they add MORE? |
| "Risk: still needs cores" | Verify: does the pack even include cores? |
| "Not tested live" | **Believe them.** Don't trust untested code. |

### Step 7: Merge Recommendation

| Score | Label | Action |
|-------|-------|--------|
| 8-10 | Master replacement | Overwrite all files, replace branch |
| 5-7 | Merge candidate | Selective cherry-pick only |
| 3-4 | Hints only | Style suggestions, ignore for runtime |
| 0-2 | Reject | Blockers present, do not merge |

**Reject if ANY of:**
- Pack breaks `greybel build` on a file that used to build
- Pack removes runtime guards we intentionally added
- Pack uses bare module headers, one-line ifs, or known crash patterns
- Pack claims "live testing" but report admits none was done

## Real Case Study: GLM 5.2 Starter Pack (2026-07-15)

**Source:** Perplexity-generated fix pack for `setup/controlcenter/bootstrap/localrecon/nscan/portscan`

### Step 1: Inventory
- 6 .src files (tools only), 1 FINAL_REPORT.md, 1 TEST_PROTOCOL.md, 1 MANIFEST.json
- **No cores** (uicore, configcore, etc.) — pack only covers user-facing tools

### Step 2: Similarity
| File | Similarity | Verdict |
|------|-----------|---------|
| yuno_nscan | 0.78 | Polish — retains get_router pattern ✅ |
| portscan | 0.80 | Polish ✅ |
| controlcenter | 0.52 | Structural rewrite (list .push() pattern) |
| yuno_bootstrap | 0.46 | Named helper extraction |
| setup | 0.37 | Linear build flow — **but with 14 one-line ifs** |
| yuno_localrecon | 0.34 | Refactored helpers |

### Step 3: P0 Scan Result
- **setup.src: 14 one-line ifs** → BLOCKER
- nscan/portscan: retained `get_router` ✅
- No bare module headers ✅
- No network_gateway ✅

### Step 4: Build Result
- 5/6 files build ✅
- **setup.src: FAIL** (one-line ifs)
- controlcenter builds ✅ (with our cores)

### Step 5: Mock Result
- 5/6 files execute ✅
- **setup.src: FAIL** (runtime crash)
- nscan: ports shown with service names ✅
- portscan: ports shown ✅

### Step 6: Report Claims vs Reality
| Claim | Reality |
|-------|---------|
| "Removed risky list blocks in setup" | True, but added 14 one-line ifs ⚠️ |
| "No live verification possible" | Admitted — respected honesty, but confirms untested |
| "Conservative bugfixes" | Fixes are real, but regressed setup |

### Step 7: Recommendation — R0 Reject

**Score: 3.5/10 as master exchange** → Do NOT overwrite hardened baseline.

**What CAN be optionally cherry-picked:**
- controlcenter `.push()` instead of multi-line list literals
- bootstrap `detectUserName()` extraction
- localrecon `printFolderFiles()` helper

**What MUST NOT be taken:**
- `setup.src` (regression)
- Portscan/nscan as a block (ours is equivalent and we trust it)

### Follow-up (same session): R1 applied
On 2026-07-15 the three safe cherry-picks were merged into the hardened branch as style-only (commit family `f72cea5` line), `setup` left multi-line. Mock rebuild stayed green. So score **as full pack** remains reject; score **as optional style hints that we already absorbed** is effectively done.
