# NVIDIA Driver Troubleshooting

## Quick Diagnose
```bash
# Is the driver loaded?
nvidia-smi
lsmod | grep nvidia
cat /proc/driver/nvidia/version 2>/dev/null

# Kernel modules available?
modinfo nvidia 2>&1 | head -5
dkms status 2>/dev/null | grep -i nvidia
find /lib/modules/$(uname -r)/kernel/nvidia* -name '*.ko' 2>/dev/null

# Boot/kernel messages
dmesg | grep -i nvidia | tail -20
journalctl -b | grep -iE 'nvidia.*fail|nvidia.*error|module.*nvidia'

# Xorg config (common boot-breaker!)
cat /etc/X11/xorg.conf 2>/dev/null   # <-- THIS FILE IS DANGEROUS
ls /etc/X11/xorg.conf.d/
cat /usr/share/X11/xorg.conf.d/10-nvidia.conf 2>/dev/null

# Services
systemctl status nvidia-powerd
systemctl status nvidia-persistenced

# Secure Boot (blocks unsigned modules)
mokutil --sb-state 2>/dev/null

# Modprobe config
cat /etc/modprobe.d/nvidia*.conf 2>/dev/null
cat /etc/modprobe.d/nvreg*.conf 2>/dev/null

# Installed packages
dpkg -l | grep -iE '^ii.*nvidia' | awk '{print $2, $3}'
```

## Common Pitfalls

### PITFALL 1: `nvidia-xconfig` writes `/etc/X11/xorg.conf` — BOOT KILLER
`nvidia-xconfig --cool-bits=12` generates a hard `xorg.conf` that **forces** the NVIDIA driver for X. If the driver module fails to load, X won't start -> black screen / Grub Rescue.

**Symptom:** Boot hangs, falls to Grub Rescue, or GDM won't start.
**Diagnose:** `cat /etc/X11/xorg.conf` -- if it exists and was generated by nvidia-xconfig, it's suspect.
**Fix:**
```bash
sudo mv /etc/X11/xorg.conf /etc/X11/xorg.conf.disabled
# Coolbits in xorg.conf.d instead (safer, won't block X if driver fails):
sudo tee /etc/X11/xorg.conf.d/20-nvidia-coolbits.conf > /dev/null <<'EOF'
Section "Device"
    Identifier "NVIDIA GPU"
    Driver "nvidia"
    Option "Coolbits" "12"
EndSection
EOF
```
**NEVER let nvidia-xconfig write xorg.conf on a laptop with hybrid graphics (Intel+NVIDIA).** Use `xorg.conf.d` snippets instead.

### PITFALL 2: `nvidia-powerd.service` fails with status 203/EXEC
The service file at `/etc/systemd/system/nvidia-powerd.service` can get corrupted by tools like Green With Envy (GWE). Status 203/EXEC means systemd can't execute the binary.

**Diagnose:**
```bash
systemctl status nvidia-powerd
ls -la /usr/bin/nvidia-powerd
cat /etc/systemd/system/nvidia-powerd.service
```

**Fix -- Restore from package default (single-line, no backslash):**
```bash
# NOTE: Use single-line commands when copy-pasting. Backslash line
# continuation (\ at end of line) can fail if trailing whitespace or
# encoding issues are introduced during paste.
sudo rm -f /etc/systemd/system/nvidia-powerd.service
sudo cp /usr/share/doc/nvidia-kernel-common-595/nvidia-powerd.service /etc/systemd/system/nvidia-powerd.service
sudo systemctl daemon-reload
sudo systemctl restart nvidia-powerd
```
```bash
# Check the package default
cat /usr/share/doc/nvidia-kernel-common-*/nvidia-powerd.service

# Replace the broken service file
sudo rm /etc/systemd/system/nvidia-powerd.service
sudo cp /usr/share/doc/nvidia-kernel-common-*/nvidia-powerd.service \
        /etc/systemd/system/nvidia-powerd.service
sudo systemctl daemon-reload
sudo systemctl restart nvidia-powerd
```

### PITFALL 3: RTX 50xx (Blackwell) -- unsupported GPU hack
RTX 5060/5070/5080/5090 Laptop GPUs (Device IDs like 2d19) may not be officially supported by older driver versions. The hack `NVreg_OpenRmEnableUnsupportedGpus=1` in `/etc/modprobe.d/nvreg_fix.conf` enables the open kernel module to bind to unsupported devices.

**Symptom:** `nvidia-smi` fails, `no CUDA-capable device is detected`, dmesg shows "unknown GPU"
**Check:**
```bash
lspci -nn | grep -i nvidia   # Note the Device ID (e.g., 2d19)
cat /etc/modprobe.d/nvreg_fix.conf
```

**Fix options:**
1. Use `nvidia-driver-595-open` (open kernel module) instead of proprietary.
2. Keep `NVreg_OpenRmEnableUnsupportedGpus=1` -- it's needed for RTX 50xx.
3. Update to the newest driver that officially supports the device.

### PITFALL 4: Secure Boot blocks kernel modules
**Symptom:** `nvidia-smi` fails, `modprobe nvidia` works but module doesn't stick across reboots, `mokutil --sb-state` shows "SecureBoot enabled".
**Note:** Ubuntu's NVIDIA modules are signed by Canonical's key so they *usually* work with Secure Boot. But combined with `OpenRmEnableUnsupportedGpus`, the module may be rejected.

### GOTCHA: `cp` fails with "Datei oder Verzeichnis nicht gefunden"
If `cp source /etc/systemd/system/somefile.service` fails with this error
even though `/etc/systemd/system/` exists, check for broken symlinks:
```bash
ls -la /etc/systemd/system/somefile.service
find /etc/systemd/system -xtype l   # find broken symlinks
```
Systemd symlinks in `*.wants/` directories can become dangling after
package upgrades or manual edits. Remove the broken symlink first:
```bash
sudo rm -f /etc/systemd/system/somefile.service   # removes broken symlink
sudo cp /usr/share/doc/nvidia-kernel-common-595/nvidia-powerd.service /etc/systemd/system/nvidia-powerd.service
```

### PITFALL 5: `/etc/modprobe.d/nvreg_fix.conf` -- custom hacks pile up
Check for accumulated hacks in `/etc/modprobe.d/`. Common files:
- `nvidia-graphics-drivers-kms.conf` -- official (modeset=1, PreserveVideoMemory)
- `nvreg_fix.conf` -- custom hacks (OpenRmEnableUnsupportedGpus, etc.)

Don't blindly remove these -- understand what each option does first.

## Module Load/Reload
```bash
# Load manually
sudo modprobe nvidia
sudo modprobe nvidia-drm
sudo modprobe nvidia-modeset
sudo modprobe nvidia-uvm

# Unload (stop display manager first!)
sudo systemctl stop gdm3   # or: sddm, lightdm
sudo rmmod nvidia-uvm nvidia-drm nvidia-modeset nvidia

# Rebuild module deps
sudo depmod -a
```

## Green With Envy (GWE) Specific
GWE (Flatpak: `com.leinardi.gwe`) can:
- Modify `nvidia-powerd.service` (breaks it)
- Run `nvidia-xconfig` (writes dangerous `xorg.conf`)
- Apply overclock settings that persist across reboots

**After GWE use, always check:**
1. `/etc/X11/xorg.conf` -- should NOT exist (use xorg.conf.d instead)
2. `systemctl status nvidia-powerd` -- should be active
3. `nvidia-smi` -- should show GPU

## Hybrid Graphics (Intel + NVIDIA)
Laptops with Intel iGPU + NVIDIA dGPU use PRIME offloading. Key files:
- `/usr/share/X11/xorg.conf.d/10-nvidia.conf` -- OutputClass for nvidia-drm
- `/usr/share/X11/xorg.conf.d/11-nvidia-offload.conf` -- AllowNVIDIAGPUScreens

**Don't create a full `xorg.conf`** -- let the OutputClass matching handle it. Only add `xorg.conf.d` snippets for specific options (like Coolbits).

## PITFALL 6: Wayland session blocks NV-CONTROL X-Extension

NV-CONTROL is an X11 extension embedded in `nvidia_drv.so`. Under Wayland (GNOME/Mutter), there is no X server, so the extension cannot exist. nvidia-settings shows a tiny menu, GWE crashes with "NV-CONTROL missing!".

**Diagnose:** `echo $XDG_SESSION_TYPE` → "wayland" = root cause. `xdpyinfo | grep -i NV` → empty.

**Fix:** Switch to X11 at GDM login (gear icon → "Ubuntu on X11"). `nvidia-smi` works under Wayland but `nvidia-smi -pl` may be blocked by laptop EC.

## PITFALL 7: Laptop EC Power Capping blocks `nvidia-smi -pl`

`sudo nvidia-smi -pl 115` returns "not supported in current scope" when the laptop's Embedded Controller enforces a low cap (e.g., 25W). `nvidia-smi -q -d POWER` shows "SW Power Cap: Active". This is NOT a driver bug — the EC controls the power budget. Options: X11 + Coolbits (may override), accept the cap, or do NOT attempt direct register writes.

## Optimus / Prime Runtime — the layer below the driver

Hardware + driver + module can all be healthy and a game still runs on the iGPU (or runs badly on a power-capped dGPU). Five userland knobs decide what actually renders each frame:

| Knob | Default | Effect |
|------|---------|--------|
| `__NV_PRIME_RENDER_OFFLOAD` | unset | When set to `1`, **forces** the next GL/Vulkan renderer onto NVIDIA, including Compositor and innocent OpenGL viewers. Sticky when exported in `.bashrc` or systemd unit. |
| `__GLX_VENDOR_LIBRARY_NAME` | unset | Picks NVIDIA libGLX even for mesa-launched apps. Sets `nvidia` as the GLX vendor globally. |
| `__GL_PRIME_RENDER_OFFLOAD` | unset | Mesa-side flag, the iGPU-→-dGPU equivalent of DRI_PRIME for GLES apps. |
| `DRI_PRIME=0\|1` | unset (0) | Mesa/EGL: 0=iGPU, 1=dGPU. No effect if NVIDIA's libGLX already swallowed the renderer. |
| `VK_ICD_FILENAMES` | unset | Force a specific Vulkan ICD; common in CI, rare in normal use. |

### PITFALL 9: `__NV_PRIME_RENDER_OFFLOAD=1` exported globally
If a `.bashrc`, `.profile`, or systemd user service exports this, **every** OpenGL/Vulkan process routes to NVIDIA — including the Wayland compositor under mutter, normal browsers (Chromium with `--use-gl=angle`), screenshot tools, gnome-system-monitor. Symptoms: high idle GPU util, CPU on iGPU sitting unused, games stutter because the dGPU is also doing Compositor work and gets EC-capped.

**Diagnose:**
```bash
env | grep -E '__NV_|__GLX_|__GL_|DRI_PRIME|VK_ICD'
```
Clean baseline is empty. Any non-empty value is suspect.

**Fix:** unset in the offending file (`.bashrc`, `.zshrc`, `~/.config/environment.d/*.conf`, `systemctl --user show <unit> | grep -i prime`).

#### Prime-ENV provenance discovery (when env vars found but source unknown)

If `env | grep __NV_` is non-empty but no user dotfile matches, the source is usually the **Wayland session launcher**, not a per-user config. Iterate all processes oldest-first; the eldest PID carrying the vars is the source:

```bash
# Source-tracing (read-only, no sudo):
for p in $(ls /proc | grep -E '^[0-9]+$' | sort -n); do
  if grep -q "__NV_PRIME_RENDER_OFFLOAD" /proc/$p/environ 2>/dev/null; then
    echo "PID=$p CMD=$(tr '\0' ' ' < /proc/$p/cmdline | head -c 80)"
  fi
done | head -10
# ↑ first PID = original source (older processes fork into newer)
```

Common culprits in order of likelihood:
1. `gdm-wayland-session` parented under `gdm-session-worker` (Zorin/Ubuntu-style: `env GNOME_SHELL_SESSION_MODE=zorin /usr/bin/gnome-session --session=zorin`)
2. `gnome-session-binary --session=zorin` (distro's specific session profile)
3. `gdm-session-worker [pam/gdm-password]` if PAM `pam_env.so` picked it up
4. `/etc/gdm3/Prime/Default` calling `/sbin/prime-offload` (distribution's GDM hook — runs `xrandr --setprovideroutputsource`, does NOT set the env vars itself)

When the source is a system-level session launcher, the **fix is a per-user override**, not editing system files (which distro upgrades overwrite):
```bash
# In ~/.bashrc or ~/.config/environment.d/nvidia-prime.conf:
unset __NV_PRIME_RENDER_OFFLOAD __GLX_VENDOR_LIBRARY_NAME __GL_PRIME_RENDER_OFFLOAD
# Then opt back in explicitly when needed:
prime-run() {
    __NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia "$@"
}
```

#### CASCADE: `apt purge nvidia-driver-595` removes `nvidia-prime`

Symptom: `prime-run` vanishes after driver upgrade. Caused by apt-cascade: a `purge` of `nvidia-driver-XXX` triggers removal of dependent packages including `nvidia-prime` (typical cascade: 30+ packages removed). Once `nvidia-prime` is gone, no package regenerates `prime-run` automatically on the next `nvidia-driver-595-open` install — `prime-run` is the canonical wrapper from `update-alternatives`.

**Diagnose:**
```bash
# Find purgelines mentioning nvidia-driver:
grep -E "Purge.*nvidia-driver|Remove.*nvidia-prime" /var/log/apt/history.log | tail -20
# Check whether nvidia-prime package is currently installed:
dpkg -l nvidia-prime | grep -E '^ii|^rc|^un'
```

**Fix:**
```bash
sudo apt install nvidia-prime
command -v prime-run && echo "repaired" || echo "still missing — rebuild wrapper manually (PITFALL 10)"
```

#### Repeated driver migrations (Churn-Pattern)

Symptom: `prime-run` vanishes; `nvidia-driver-595-open` and `nvidia-driver-595` alternate in /var/log/apt/history.log between `Install` / `Reinstall` / `Purge`. Each transition churns the kernel-module compilation state and may re-trigger the cascade.

**Diagnose:**
```bash
grep -E "nvidia-driver-595" /var/log/apt/history.log | awk '{print $1, $4}' | sort | uniq -c | sort -rn | head -10
```

**Mitigation:** Decide on ONE driver flavor (`-open` or proprietary) and stick with it. Avoid mixed `nvidia-driver-595-open ↔ nvidia-driver-595` cycles unless a specific bug forces the switch.

### PITFALL 10: `prime-run` is not a shipping binary
`/usr/bin/prime-run` does NOT come pre-installed. The `nvidia-prime` package ships `prime-select`, `prime-switch`, `prime-offload`, `get-quirk-options` in `/usr/sbin/` and `/usr/bin/`. The `prime-run` wrapper is generated at install time. If apt-purged and reinstalled out-of-order, it can vanish.

**Diagnose (no install needed):**
```bash
dpkg -L nvidia-prime | grep -E 'prime-(run|select|offload)'   # files the package owns
apt download nvidia-prime && dpkg-deb --contents nvidia-prime_*.deb | grep -E 'bin|sbin'
```

If `prime-run` is genuinely missing while `nvidia-prime` is installed:
```bash
sudo apt reinstall nvidia-prime
# or rebuild the wrapper manually:
sudo tee /usr/bin/prime-run >/dev/null <<'EOF'
#!/bin/sh
export __NV_PRIME_RENDER_OFFLOAD=1
export __GLX_VENDOR_LIBRARY_NAME=nvidia
export __GL_PRIME_RENDER_OFFLOAD=1
exec "$@"
EOF
sudo chmod +x /usr/bin/prime-run
```

### PITFALL 11: Vulkan "works" without `vulkaninfo`
`vulkaninfo` from `vulkan-tools` is the canonical check, but the package is **not** a hard dependency of `libnvidia-gl-595` and is often missing. The ICD presence still proves Vulkan works:

```bash
# Sufficient signal of Vulkan readiness:
cat /usr/share/vulkan/icd.d/nvidia_icd.json          # must list libGLX_nvidia.so.0
dpkg -L libnvidia-gl-595:amd64 | grep -iE 'vulkan|icd'
libvulkan=$(python3 -c 'import ctypes.util; print(ctypes.util.find_library("vulkan"))')
python3 -c "import ctypes; ctypes.CDLL('$libvulkan'); print('loader OK')"
```

If `nvidia_icd.json` is present and dynamic-loadable, Vulkan works for any game — do not block diagnosis on `vulkaninfo`.

### PITFALL 12: `powerprofilesctl balanced` quietly throttles gaming
GNOME `powerprofilesctl` defaults to `balanced` on laptops. This downclocks CPU and can co-act with the EC GPU cap. For desktop gaming, set `performance`:

```bash
powerfilesctl list                  # current profile
powerfilesctl set performance
powerfilesctl get                   # verify
```

Tuned profiles (`tuned-adm active`) interact: tuned's `balanced` + powerprofiles `balanced` = double-throttle. Pick one.

## PITFALL 8: nvidia-settings version vs driver version mismatch

Ubuntu Noble ships `nvidia-settings 510` + `libxnvctrl0 510` but driver is `595`. The NV-CONTROL X-Extension protocol changes between major versions → extension silently fails to initialize. `nvidia-settings --version` vs `nvidia-smi` driver version reveals the mismatch. Fix: extract matching nvidia-settings from NVIDIA's .run installer, or use `nvidia-smi` CLI as workaround.

## Coolbits: Use OutputClass, Not Device Section

```ini
# CORRECT — OutputClass (matches existing NVIDIA OutputClass)
Section "OutputClass"
    Identifier "nvidia"
    MatchDriver "nvidia-drm"
    Driver "nvidia"
    Option "Coolbits" "28"
EndSection
```

Coolbits values (additive): 8=GPU-Clock, 4=VRAM, 16=Voltage, **28=all three**. Requires X11 session, KMS active (nvidia_drm + nvidia_modeset loaded), and reboot.

## Boot-Loop Recovery (wenn nvidia-smi fail nach GPU-Tweak)

**Symptom:** `nvidia-smi` meldet "NVIDIA-SMI has failed because it couldn't communicate with the NVIDIA driver", System bootet nicht mehr.

**Top 3 Ursachen:**
1. Kaputtes `/etc/X11/xorg.conf` von `nvidia-xconfig`
2. Korrumpiertes `nvidia-powerd.service` (z.B. durch GWE)
3. Kernel-Update ohne Treiber-Rebuild

**Recovery:**
```bash
# 1. xorg.conf prüfen und entfernen
cat /etc/X11/xorg.conf 2>/dev/null && echo "⚠️ BOOT-KILLER gefunden!"
sudo mv /etc/X11/xorg.conf /etc/X11/xorg.conf.disabled-by-yuno

# 2. Treiber neu laden
sudo modprobe nvidia nvidia-drm nvidia-modeset

# 3. powerd wiederherstellen
sudo cp /usr/share/doc/nvidia-kernel-common-*/nvidia-powerd.service \
        /etc/systemd/system/nvidia-powerd.service
sudo systemctl daemon-reload && sudo systemctl restart nvidia-powerd

# 4. Verifizieren
nvidia-smi
```

**Prävention:** NIEMALS `nvidia-xconfig` auf Optimus-Laptops. Timeshift vor Tweaks.
