# CDP Cookie-Bridge — Login-Once Helper für Auth-gated Webseiten

> Pattern für Fälle wo eine Webseite User-Login erfordert (Nexus Mods, GitHub Enterprise, Discord-Webhooks, etc.) und die regulären Web-Tools (`web_search`, `web_extract`, Firecrawl) entweder nicht konfiguriert oder durch Cloudflare/JS-Rendering blockiert sind.
>
> **Last verified:** 2026-07-04 (City-of-Dreams-CP77-Modding-Session)

## Problem-Cluster

Drei Symptome, alle mit der gleichen Ursache: **Auth-gated Content ohne API-Key-Zugang**:

1. **Cloudflare-Block:** `curl` einer Nexus-Seite → "Just a moment..." (JS-Challenge)
2. **Encryption-Lock:** `Cookies`-SQLite-DB ist da, aber `value`-Spalte leer (`encrypted_value` benötigt Portal-Encryption-Key)
3. **Web-Tool nicht konfiguriert:** Firecrawl-Key fehlt im Hermes-Profil → `web_extract` antwortet mit Fehler

**Konventioneller Workaround:** User loggt sich manuell ein, exportiert Cookie als Netscape-Format, legt es in eine Datei, Skript liest es. Funktioniert, ist aber bei jeder neuen Session kaputt.

## CDP-Bridge-Pattern (3 Schritte, ~30 Sek)

Statt Cookies aus der SQLite-DB zu extrahieren: separaten Browser-Prozess öffnen mit DevTools-Protocol, User loggt sich EINMAL ein, Cookies via CDP auslesen.

### Schritt 1: Separate Browser-Instanz öffnen

NICHT den laufenden Browser killen — separater Profil-Ordner = keine Kollision mit User-Tabs.

```bash
# Eigener User-Dir (verhindert Lock-Konflikt mit laufendem Brave/Chrome)
/usr/bin/brave-browser \
  --user-data-dir=/tmp/brave-debug-profile \
  --remote-debugging-port=9333 \
  --remote-allow-origins='*' \
  --no-first-run \
  --no-default-browser-check \
  about:blank
```

**Wichtig:** `terminal(background=true)` benutzen, nicht `nohup`/`&`/`disown` (Hermes rejected das).

**Pitfall:** Port 9222 ist Standard — wenn schon belegt (z.B. Chrome DevTools), anderen Port wählen (9333, 9444, etc.).

### Schritt 2: User-Login (manuell)

User öffnet das neue Browser-Fenster, navigiert zur gewünschten Seite, loggt sich ein. **EINMAL** pro Session.

```bash
# Verifizieren dass CDP antwortet
curl -s http://localhost:9333/json/version | python3 -m json.tool | head -5
```

### Schritt 3: Cookies via CDP extrahieren

```python
import json, urllib.request, sqlite3
from pathlib import Path

CDP_URL = "http://localhost:9333"

# Alle Tabs/Pages listen
tabs = json.loads(urllib.request.urlopen(f"{CDP_URL}/json/list").read())

# Tab mit der Ziel-Domain finden ODER neuen Tab erzeugen
# (Für unser Pattern: einfach alle Cookies aggregieren, egal aus welchem Tab)

# Cookie-Export via CDP-Domain-Endpoint
import websocket  # pip install websocket-client (oder via apt python3-websocket)

ws_url = tabs[0]["webSocketDebuggerUrl"]
ws = websocket.create_connection(ws_url)

# Network.getCookies für alle relevanten Domains
ws.send(json.dumps({
    "id": 1,
    "method": "Network.getCookies",
    "params": {"urls": ["https://www.nexusmods.com/", "https://nexusmods.com/"]}
}))
result = json.loads(ws.recv())

# In Netscape-Format exportieren (curl/requests/wget kompatibel)
COOKIE_FILE = Path("/home/bratan/cp77-modding/.nexus-cookies.txt")
with open(COOKIE_FILE, "w") as f:
    f.write("# Netscape HTTP Cookie File\n")
    f.write("# Generated by Yuno CDP-Bridge. DO NOT SHARE.\n\n")
    for c in result["result"]["cookies"]:
        # Format: domain  includeSub  path  secure  expires  name  value
        domain = c["domain"]
        include_sub = "TRUE" if domain.startswith(".") else "FALSE"
        secure = "TRUE" if c.get("secure") else "FALSE"
        path = c["path"]
        expires = str(c.get("expires", 0)) if c.get("expires", -1) > 0 else "0"
        name = c["name"]
        value = c["value"]
        f.write(f"{domain}\t{include_sub}\t{path}\t{secure}\t{expires}\t{name}\t{value}\n")

ws.close()
print(f"✅ {len(result['result']['cookies'])} Cookies → {COOKIE_FILE}")
```

### Verwendung

```bash
# Download mit Cookie-Auth
curl --cookie /home/bratan/cp77-modding/.nexus-cookies.txt \
     -A "Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 Chrome/120" \
     -o mod.zip \
     "https://www.nexusmods.com/cyberpunk2077/mods/1234?tab=files&file_id=5678"
```

## Warum nicht die SQLite-Cookies-DB direkt?

Chromium-basierte Browser (Brave v1.92+, Chrome v130+, Edge) verschlüsseln die `value`-Spalte der `Cookies`-Tabelle mit einem `os_crypt.encrypted_key` aus `Local State`. Auf Linux nutzt Brave seit v1.92 einen **Portal-basierten** Encryption-Mechanismus (via `xdg-desktop-portal` + `Secret Service`/KWallet) statt einer direkten AES-Schlüsselableitung.

**Konsequenz:**
- `value`-Spalte in SQLite ist leer
- `encrypted_value` ist AES-GCM-verschlüsselt mit Session-spezifischem Schlüssel
- Ohne den Schlüssel vom Portal sind die Cookies nicht lesbar

**Frühere Lösungen (alle obsolet seit v1.92):**
- `localcrypto`-Python-Paket (Windows/Mac only)
- Hardcoded `peanuts`-Key (gepatcht in Brave 1.50+)
- `safe_storage` Chromium-API (Linux ohne Portal nutzt das, aber neue Brave-Versionen nicht mehr)

**CDP-Bridge umgeht das komplett** weil der Browser-Prozess die Cookies bereits decrypted im Speicher hat — `Network.getCookies` liefert Klartext.

## Session-Cleanup

Nach getaner Arbeit den separaten Browser killen:

```bash
pkill -f "user-data-dir=/tmp/brave-debug-profile"
rm -rf /tmp/brave-debug-profile
# Cookie-File: User entscheidet (sicher aufbewahren für nächste Session ODER löschen)
```

## Pitfalls

1. **CDP-Port belegt** — Anderen Port wählen (`lsof -i :9222` checken)
2. **Origin-Schutz** — `--remote-allow-origins='*'` ist nötig für externe Clients (Chrome 111+ Standard-Schutz)
3. **`/usr/bin/brave-browser` vs `brave-browser-stable`** — Flatpak-System: `/var/lib/flatpak/exports/bin/brave` oder `flatpak run com.brave.Browser`. Snap: `/snap/bin/brave`.
4. **Trennung von Haupt-Browser wichtig** — Eigener User-Dir zwingend, sonst kollidieren zwei Profile auf demselben Browser-Prozess
5. **HTTPS-only** — `Network.getCookies` mit `urls`-Array filtert nach Scheme. `http://`-Cookies für `localhost`-Dev-Server nicht inkludiert
6. **Cookie-Expiry** — Falls User-Session abläuft (Nexus: ~24h), muss neu eingeloggt werden. Skript neu starten.
7. **Wert von `expires`** — CDP liefert Unix-Timestamp in Sekunden, NICHT Chromium-Microseconds (anders als SQLite-Format). Negativ/0 = Session-Cookie.
