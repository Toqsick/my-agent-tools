# Waydroid Repair Trace — 2026-07-04

Platform: Ubuntu 24.04, NVIDIA RTX 5060 (Driver 595.71.05), Wayland (GNOME)
Waydroid: 1.6.2, installed but stopped, binder devices missing

## Initial State

```
waydroid status:
  Session:   STOPPED
  Container: STOPPED
  Vendor:    MAINLINE
```

## Repair Sequence

### Step 1: Kernel Module

```bash
sudo modprobe binder_linux
ls /dev/anbox-*
# → /dev/anbox-binder, /dev/anbox-vndbinder, /dev/anbox-hwbinder
```

### Step 2: LXC Mount Entries

Added to `/var/lib/waydroid/lxc/waydroid/config`:
```
lxc.mount.entry = /dev/anbox-binder dev/anbox-binder none bind,create=file 0 0
lxc.mount.entry = /dev/anbox-vndbinder dev/anbox-vndbinder none bind,create=file 0 0
lxc.mount.entry = /dev/anbox-hwbinder dev/anbox-hwbinder none bind,create=file 0 0
```

### Step 3: Container Restart

```bash
sudo systemctl restart waydroid-container.service
```

First attempt failed with `journalctl` showing: `binder_open: 2041:5463 binder_version mismatch`

The issue was that the host-permissions XML at `/var/lib/waydroid/host-permissions/1000-wayland.xml` was not generated by `waydroid init` — it's generated at runtime when the Android hardware service starts. Since the service couldn't start (no binder), the XML wasn't created.

### Step 4: cgroup2 Check

On Ubuntu 24.04, cgroup2 is the default. Confirmed working:
```
stat -fc %T /sys/fs/cgroup/ → cgroup2fs
```

No cgroup modification was needed.

## Key Lesson

The **host-permissions XML must exist before the container can fully start**, but it's only created when the hardware service first successfully binds. This creates a circular dependency:
1. Container starts → needs binder → binder exists
2. Hardware service starts → creates /var/lib/waydroid/host-permissions/1000-wayland.xml
3. Without LXC mount entries, container doesn't see binder devices
4. Without binder, hardware service doesn't start → no XML generated

**Fix order matters:** binder module → LXC mount entries → restart service. The XML is created on the first successful restart.
